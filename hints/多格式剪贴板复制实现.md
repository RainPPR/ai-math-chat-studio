# **多格式剪贴板复制实现**

[https://gemini.google.com/app/5133fc23f96c6cf5](https://gemini.google.com/app/5133fc23f96c6cf5)

*User prompt: 像 Gemini 网页版中，复制消息，粘贴到纯文本里面是 Markdown 源码，粘贴到 Word 里面自带格式，是怎么实现的？*

Response: 这其实利用了现代系统剪贴板的一个核心机制：**一次复制操作，可以同时写入多种数据格式（MIME 类型）。**

并不是网页端在粘贴时去判断“你要粘贴到哪”，而是在你点击“复制”那一刻，前端就已经把**两份不同格式的数据**一起塞进了系统剪贴板。

## **核心实现原理**

系统剪贴板就像一个包含不同口袋的容器，网页前端会在里面放置不同版本的内容：

 `系统剪贴板 (Clipboard Payload)`  
 `├── text/plain ──> "# 标题\n这是 **加粗** 文本"   (纯 Markdown 源码)`  
 `└── text/html  ──> "<h1>标题</h1><p>这是 <strong>加粗</strong> 文本</p>" (HTML 格式)`

当你执行粘贴时，**接收内容的软件（如 Word 或记事本）会根据自己的能力选择最合适的口袋**：

> * **记事本 / VS Code / 终端**：只支持纯文本，所以主动拉取 text/plain 里的内容 → 得到 **Markdown 源码**。  
> * **Word / 飞书 / 微信公众号编辑器**：支持富文本，会优先选取 text/html 里的内容 → 直接解析并渲染为 **格式化文本**。

## **前端核心 API 代码**

在现代浏览器中，主要通过 ClipboardItem API 实现多格式并发写入：

`async function copyMarkdownWithHtml(markdownText, htmlText) {`  
  `try {`  
    `// 1. 将 Markdown 和 HTML 分别包装为指定 MIME 类型的 Blob 对象`  
    `const textBlob = new Blob([markdownText], { type: 'text/plain' });`  
    `const htmlBlob = new Blob([htmlText], { type: 'text/html' });`

    `// 2. 构建包含多格式的 ClipboardItem`  
    `const item = new ClipboardItem({`  
      `'text/plain': textBlob,`  
      `'text/html': htmlBlob`  
    `});`

    `// 3. 一次性写入系统剪贴板`  
    `await navigator.clipboard.write([item]);`  
    `console.log('复制成功！');`  
  `} catch (err) {`  
    `console.error('复制失败：', err);`  
  `}`  
`}`

`// 示例使用`  
`const rawMarkdown = "### 提示\n这是一段 **加粗** 的文字。";`  
`const renderedHtml = "<h3>提示</h3><p>这是一段 <strong>加粗</strong> 的文字。</p>";`

`copyMarkdownWithHtml(rawMarkdown, renderedHtml);`

## **细节优化：为了让 Word 粘贴效果更好**

直接传入原生 HTML 时，Word 可能会因为缺乏样式继承导致字号、字体不符合预期。实际开发中（例如 Gemini 或 ChatGPT 网页版），还会做以下优化：

> 1. **内联样式 (Inline CSS)**：在 text/html 的 Blob 中，将样式直接写在 HTML 标签上（如 \<p style="font-family: sans-serif; color: \#333;"\>），保证 Word 能精准还原颜色和边距。  
> 2. **附加 HTML 完整骨架**：部分版本的 Word 对单独的 \<p\> 标签兼容性不好，最好在 HTML 字符串外包裹完整骨架：  
>    `<html>`  
>      `<body>`  
>        `<!-- 复制的 HTML 内容 -->`  
>      `</body>`  
>    `</html>`

*User prompt: 还可以附上哪些 MIME？详细列举*

Response: 除了最常用的 text/plain 和 text/html，系统剪贴板（以及 Web Clipboard API）还支持写入**多种其他 MIME 类型**。

通过组合不同的 MIME 类型，你可以实现“在微信发图片，在 Excel 黏贴成表格，在 VS Code 黏贴成纯代码”这样极度智能的复制体验。

以下是常见的 MIME 类型分类及其实际应用场景：

## **1\. 文本与文档类 MIME 类型**

| MIME 类型 | 常见用途与场景 | 谁会读取它？ |
| :---- | :---- | :---- |
| **text/plain** | 纯文本、原始 Markdown、代码块 | 记事本、终端、VS Code、搜索框 |
| **text/html** | 带有样式的富文本、表格、超链接 | Word、飞书、微信公众号、语雀 |
| **text/rtf** | 富文本格式 (Rich Text Format) | 苹果备忘录 (Apple Notes)、WordPad、Pages、部分原生桌面应用 |
| **text/csv** | 逗号分隔的结构化数据 | Excel、Google Sheets、Numbers（直接识别为单元格而不是一行文本） |
| **text/uri-list** | 一个或多个 URL 链接列表 | 浏览器标签栏、书签栏、文件管理器（可以直接拖/粘生成快捷方式） |

## **2\. 图像与媒体类 MIME 类型**

剪贴板**允许同时放入“文字版本”和“图片版本”**。例如，你复制一个图表，可以同时写入 image/png 和 text/html，这样在聊天软件里贴出的是图片，在 Word 里贴出的是图表结构。

| MIME 类型 | 常见用途与场景 | 谁会读取它？ |
| :---- | :---- | :---- |
| **image/png** | **最通用**的无损图片格式 | 微信、QQ、Photoshop、Figma、Slack |
| **image/jpeg** | 压缩照片（部分现代浏览器支持） | 图片编辑器、聊天工具 |
| **image/svg+xml** | 矢量图代码 | Figma、Illustrator、Sketch（直接粘贴为可编辑的矢量图层） |
| **image/webp** | 现代高效图片格式 | 浏览器、现代图像处理软件 |

## **3\. Web Custom Formats (Web 自定义格式)**

在过去的 W3C 规范中，浏览器为了安全，只允许写入极少数被“安全洗白”的标准 MIME 类型（如 plain, html, png）。但现在的现代浏览器引入了 **Web Custom Formats** 机制。

只要在 MIME 类型前加上 **web 前缀**，你就可以写入任何自定义的数据结构（例如 JSON）：

| 自定义 MIME 示例 | 场景与目的 | 典型应用示例 |
| :---- | :---- | :---- |
| **web application/json** | 传递复杂的结构化对象 | 在自研的 Web 系统内部，复制一个包含完整配置/状态的组件 |
| **web text/vnd.mycompany.figma** | 保存画布节点数据 | **Figma / Canva**：复制图层时，除了生成普通 HTML/图片，还会将节点 JSON 结构存在自定义 MIME 中，以便在同一软件内粘贴时完整还原图层与属性 |
| **web text/x-vscode-editor-data** | 带有 IDE 元数据的代码 | **VS Code**：复制时带上语法高亮信息、列选择状态等 |

## **真实应用场景：多 MIME 组合示例**

假想你做了一个**数据分析可视化平台**，用户点击“复制图表”时，你可以一次性给剪贴板注入 4 个“口袋”：

`const item = new ClipboardItem({`  
  `// 1. 粘贴到纯文本/终端：给一句话总结`  
  `'text/plain': new Blob(["2026年第一季度 sales 数据：120万 (同比增长 15%)"], { type: 'text/plain' }),`

  `// 2. 粘贴到 Excel：直接变成规整的 CSV 单元格`  
  `'text/csv': new Blob(["月份,销售额\n1月,30万\n2月,40万\n3月,50万"], { type: 'text/csv' }),`

  `// 3. 粘贴到 微信/Photoshop：直接呈现一张渲染好的高清晰 PNG 图表`  
  `'image/png': chartPngBlob,`

  `// 4. 粘贴到 同套系统：还原为可交互的 JSON 图表配置`  
  `'web application/json': new Blob([JSON.stringify(chartConfig)], { type: 'web application/json' })`  
`});`

`await navigator.clipboard.write([item]);`

### **结果：**

> * 粘贴到 **微信** → 收到 **图片**。  
> * 粘贴到 **Excel** → 自动变成 **表格**。  
> * 粘贴到 **TXD/记事本** → 收到 **纯文本总结**。  
> * 粘贴回 **你的系统** → 直接 **加载图表对象**。

## **注意事项与浏览器限制**

> 1. **同源/跨域安全限制**：自定义 MIME 类型 (web ...) 通常只能在支持该规范的现代浏览器（Chrome 104+、Edge 等）中生效，且读取方需要主动尝试获取该特定 MIME 类型。  
> 2. **格式数量与大小**：虽然允许同时塞入多个 MIME，但尽量控制数据体积（特别是同时塞入大分辨率的 image/png 和巨大文本时），避免占用过高内存。

*User prompt: Word 里面粘贴，是 text/html 还是 text/rtf*

Response: 从网页（如 Gemini、ChatGPT）复制并直接粘贴到 Word 时，Word 读取并解析的是 **text/html**。

## **为什么是 text/html？**

> 1. **浏览器的原生行为**：在网页里复制内容时，浏览器默认只会向剪贴板里装入 text/plain（纯文本）和 text/html（富文本），**不会原生生成 text/rtf**。因此 Word 在接收网页复制的内容时，只能从 text/html 中解析样式。  
> 2. **Word 的解析能力**：现代 Word 内置了强大的 HTML 渲染引擎，能够将 HTML 标签（如 \<h1\>、\<table\>、\<b\>）和内联 CSS 样式（如颜色、字号、间距）实时转换成 Word 内部的 OpenXML 文档格式。

## **如果剪贴板里同时有 text/html 和 text/rtf，Word 选哪个？**

如果你使用的某些桌面软件（如 WordPad、某些富文本编辑器）在复制时同时写入了 text/html 和 text/rtf：

> * **默认快捷键 (Ctrl \+ V)**：Word 的默认读取优先级是 **HTML 格式 (text/html) \> RTF 格式 (text/rtf)**。因为 HTML 能更好地还原现代排版、表格布局和 CSS 样式。  
> * **Word 两者都兼容**：Word 并没有放弃 RTF，只要剪贴板里有，它随时准备读取。

## **验证小技巧：在 Word 里查看剪贴板格式**

想亲自验证这一点，可以在 Word 中做个小实验：

> 1. 在网页上复制一段带格式的文字。  
> 2. 打开 Word，按下快捷键 **Ctrl \+ Alt \+ V**（或者点击菜单栏的“粘贴” → “选择性粘贴”）。  
> 3. 弹出的对话框中会明确列出当前剪贴板里 Word 能识别的所有数据类型：  
   * **HTML 格式**（即 text/html）  
   * **无格式 Unicode 文本**（即 text/plain）

如果你是从桌面版 WordPad 复制，这里就会额外出现 **“带格式文本 (RTF)”** 的选项。

*User prompt: 我从 Gemini 复制的，这是选择性粘贴，里面的是什么意思，是 text/plain text/html 的效果吗？*

Response: 没错，**这完全就是剪贴板里的 text/plain 和 text/html 在 Word 界面上的对应呈现！**

你截图中看到的这三个选项，就是 Word 将系统剪贴板中的各种 MIME 格式翻译成用户能看懂的语言。

## **选项与 MIME 类型的精准对照**

| 界面上的选项 | 对应的剪贴板 MIME | 粘贴后的实际效果 |
| :---- | :---- | :---- |
| **HTML 格式** | text/html | **带排版的富文本**。Word 会解析里面的 HTML 标签，渲染出加粗、高亮、列表、表格和样式。 |
| **无格式的 Unicode 文本** | text/plain | **Markdown 源码 / 纯文本**。完全剥离样式，只保留文字本身（在 Gemini 里复制的就是 \# 标题、\*\*加粗\*\* 这种 Markdown 语法）。 |
| **无格式文本** | text/plain | 同样是纯文本，属于 Windows 历史遗留兼容项（见下文解释）。 |

## **详细解析：这三个选项具体代表什么？**

### **1\. HTML 格式（对应 text/html）**

> * **这是 Word 默认使用的粘贴格式。**  
> * 当你直接按下 Ctrl \+ V 时，Word 默认就会选这个。它会把 Gemini 网页生成的 HTML 代码翻译成 Word 自身的排版规则。

### **2\. 无格式的 Unicode 文本（对应现代 text/plain）**

> * **这就是你要的 Markdown 源码。**  
> * 现代浏览器和操作系统统一使用 Unicode 编码（UTF-16），当你用 JS 写入 text/plain 时，系统底层就会生成这个 CF\_UNICODETEXT 格式。  
> * 如果你想在 Word 里直接看 Markdown 原始语法，选这个就对啦。

### **3\. 无格式文本（历史遗留机制）**

> * 为什么会有两个“无格式”？这是 Windows 系统为了兼容几十年前老软件留下的机制：  
  * **无格式文本**：指 ANSI 编码的纯文本（老 Windows 格式 CF\_TEXT）。  
  * **无格式的 Unicode 文本**：支持多国语言的 Unicode 纯文本（CF\_UNICODETEXT）。  
> * **在今天的 Windows 系统中，系统会自动将网页的 text/plain 同时转换出这两个版本**，以防你粘贴到某些 20 年前开发的老软件里出现乱码。对你来说，在 Word 里选它们两个效果是一模一样的。

**总结：**

> * 想拿 **带颜色的漂亮排版** → 选 **HTML 格式**  
> * 想拿 **Markdown 源码** → 选 **无格式的 Unicode 文本**（或 无格式文本）
